Rscopulas includes two complementary benchmarking surfaces: a cross-language harness that measures wall-clock time for Rust, Python, and R on identical inputs, and Criterion microbenchmarks that give per-iteration statistics for Rust-only code paths. The two surfaces use different methodologies — do not compare numbers from one directly against the other.

## Cross-language harness results

The table below shows representative results from the mixed R-vine workload in the cross-language harness. Each row uses the same fixture JSON and iteration counts for all three implementations. **Speedup** is R mean time divided by rscopulas mean time — higher is better.

| Workload | Rust vs R | Python vs R | Mean times (Rust / Python / R) |
| --- | ---: | ---: | --- |
| Mixed R-vine **fit** | **22×** | **19×** | 0.75 ms / 0.86 ms / 16.5 ms |
| Mixed R-vine **sample** | **46×** | **40×** | 2.5 ms / 2.9 ms / 114.1 ms |
| Mixed R-vine **`log_pdf`** | **514×** | **426×** | 4.8 µs / 5.8 µs / 2.47 ms |

Other cases from the same run:

| Workload | Rust vs R | Python vs R |
| --- | ---: | ---: |
| Gaussian / Student t / Clayton / Frank / Gumbel copula **fit** | 130× / 27× / 95× / 47× / 41× | 113× / 40× / 79× / 40× / 38× |
| Same five families, **`log_pdf`** | 255× / 43× / 148× / 86× / 115× | 101× / 35× / 53× / 47× / 48× |
| Gaussian / Student t **sample** | 10× / 8.8× | 10× / 8.8× |
| Gumbel / Frank / Clayton **sample** | 4.9× / 3.4× / 2.8× | 3.3× / 3.2× / 2.6× |
| Pair kernels (density, h, inverse h), Gaussian / Clayton / Frank | 509× / 378× / 608× | 51× / 56× / 69× |
| Pair kernels, Student t / Gumbel 180° / Khoudraji | 39× / 166× / 1000× | 22× / 48× / 801× |

Every case is faster than R. 20 of the 25 are at least 10× faster; the five below that are the single-family samplers, which draw 10 000 bivariate observations in 0.08–0.36 ms. Up to release 0.6.0 R was faster at Clayton and Frank sampling (0.55× and 0.11×). The samplers use every core, R uses one; at a million draws twelve threads are 7.5× faster than one.

<Note>
From release 0.6.1 the Gaussian, Student t, Clayton, Frank and Gumbel samplers draw in independent blocks of 256 rows so that they can run in parallel. A given seed therefore produces a different sample than in 0.6.0 and earlier. The sample does not depend on the number of threads, and Python, Rust and JavaScript still agree for the same seed.
</Note>

## Against pyvinecopulib, feature by feature

`benchmarks/compare_pyvinecopulib_features.py` times 73 operations both libraries share: density, both h-functions and both inverses of ten pair families, pair fits and family selection, and vine density, Rosenblatt transforms, sampling and fitting. Both sides get the same number of threads.

| Threads each | rscopulas slower in | Where |
| --- | ---: | --- |
| 1 | 6 of 73 | TLL pair fit 0.53×, BB7 density 0.74×, Frank density 0.75×, BB1 density 0.90×, Clayton inverse h 0.90–0.96× |
| 12 | 0 of 73 | |

Release 0.6.0 was slower in 22 of the 73 on one thread. pyvinecopulib returns the density and rscopulas its logarithm, which costs one extra `ln` per point in the density rows. The [comparison page](/performance/comparison) covers which models the two libraries select.

The Python and Rust numbers track each other closely because both call the same Rust core. The large `log_pdf` advantage comes from the vine density evaluation being entirely in Rust with no interpreter overhead on the hot path.

<Note>
These numbers are from one run of release 0.6.1 on 2026-11-18 on an Apple M3 Pro, against R 4.3 with `copula` and `VineCopula` and against pyvinecopulib 0.7.6. The machine was running other applications, so single figures move by 10–20 % between runs. Results depend on CPU, memory bandwidth, and package versions. Run the harness locally to get numbers relevant to your hardware.
</Note>

## Release 0.5.0 against 0.4.0

Release 0.5.0 reworked the numerical core. The table shows measured speed-ups on an Apple M3 Pro, both builds run back to back (medians; all 110 cases are in `benchmarks/perf/`; figures move by about 10 % between runs). The cross-language table above was measured after this work.

| Case | 0.5.0 vs 0.4.0 |
| --- | ---: |
| Nested Frank / Clayton HAC sampling (now exact) | 262× / 147× |
| Gaussian vine `log_pdf`, d = 10 | 46× |
| D-vine / C-vine / R-vine fit, default family set, d = 6 | 33× / 32× / 11× |
| Pair fit, default family set | 30× |
| Factor copula fit | 26× |
| Student t copula fit | 15× |
| Inverse h-functions without a closed form | 7–14× |
| Mixed vine sampling | 7–8× |
| Mixed vine `log_pdf` | 4× |
| Scalar densities and h-functions of Archimedean pair families | unchanged |

24 of the 110 cases are at least 10× faster and none is slower. Reproduce with:

```bash
cargo run --release -p rscopulas --example perf_suite -- --compare benchmarks/perf/baseline-0.4.0.json
```

## Reproducing the benchmarks

Both benchmark surfaces are available in the rscopulas source repository on [GitHub](https://github.com/alexwox/rscopulas).

### Cross-language harness

Clone the repository and run the harness from the root:

```bash
python benchmarks/run.py
```

Filter by language or workload:

```bash
python benchmarks/run.py --implementation rust --case vine
```

Results are written locally to `benchmarks/output/latest.md`.

### Criterion microbenchmarks (Rust only)

```bash
cargo bench -p rscopulas
```

Criterion runs the Rust code paths and prints per-iteration statistics. Use this surface to isolate individual Rust functions rather than comparing across languages.

## How the harness works

The cross-language harness orchestrates three runners — Rust, Python, and R — over a shared manifest that defines:

- **Cases** — workload name, fixture data, and which implementations to run.
- **Iteration counts** — each case specifies how many repetitions to time.
- **Fixture JSON** — the same input data is loaded by all three runners, guaranteeing apples-to-apples comparisons.

The harness covers the following workloads by default:

<AccordionGroup>
  <Accordion title="Single-family copulas">
    `log_pdf`, `fit`, and `sample` for the single-family Archimedean and Gaussian models.
  </Accordion>
  <Accordion title="Pair copula kernels">
    Density and h-function / h-inverse kernels for pair copulas, including the Khoudraji asymmetric composition (`pair_khoudraji_kernels`).
  </Accordion>
  <Accordion title="Mixed R-vine">
    End-to-end `log_pdf`, `sample`, and `fit` for a mixed-family R-vine — the workload shown in the results table above. This is the most realistic benchmark because it exercises the full vine traversal and pair-copula dispatch.
  </Accordion>
</AccordionGroup>

## Harness vs Criterion — what each measures

| | Cross-language harness | Criterion |
| --- | --- | --- |
| Languages | Rust, Python, R | Rust only |
| Overhead included | Interpreter startup, FFI, JSON fixture load | None — pure Rust |
| Output | `benchmarks/output/latest.md` | Terminal / Criterion HTML reports |
| Best for | Comparing rscopulas against R; regression tracking | Profiling individual Rust functions |

Because the harness includes Python interpreter and FFI overhead in Python timings, and R package load time in R timings, harness wall times are higher than Criterion per-iteration times for equivalent Rust operations. Use Criterion when you want to isolate a specific Rust code path; use the harness when you want end-to-end comparisons across languages.
