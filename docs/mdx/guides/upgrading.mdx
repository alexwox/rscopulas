---
title: "Upgrading"
description: "What changes in your results or your code when you move between rscopulas versions."
---

This page lists, newest first, the changes that can alter your results or break
your code when you upgrade. Releases that only add features are not listed.
The full record is in the
[changelog](https://github.com/alexwox/rscopulas/blob/master/CHANGELOG.md).

The stored vine format (`format_version: 1`) has not changed since 0.3, so
vines saved by 0.3 or later still load.

## 0.6.1

Samples for a given seed change. The Gaussian, Student t, Clayton, Frank and
Gumbel samplers, and flat hierarchical trees, now draw in blocks of 256 rows,
each from its own generator seeded by yours. The distributions are the same;
only the stream differs. Results do not depend on the number of threads, and
Python, Rust and WebAssembly still agree for the same seed.

Re-record any stored samples or seeded test expectations. Densities,
h-functions and fits are unchanged within rounding.

## 0.6.0

No changes to existing results. In Rust, `InputError` has a new variant,
`InvalidArgument`; add an arm if you match on the enum exhaustively.

## 0.5.0

- **Nested Clayton and Frank sampling is corrected.** Earlier versions drew
  the frailty of a Clayton node nested in a Clayton node (or Frank in Frank)
  from an approximation that missed the model's distribution. Samples from
  such trees were wrong and now change; redo any simulation built on them.
  Nested Gumbel and exchangeable trees are unchanged. See
  [hierarchical Archimedean copulas](/guides/hierarchical-archimedean).
- **Fitted parameters may move.** Pair, vine, Khoudraji and factor fits use
  new optimizers. Log-likelihoods are equal or higher, so selected families
  and parameters can differ slightly from 0.4.
- **Tail values move by up to 1e-10 relative.** The normal distribution
  function is now accurate in the tails; results that depend on it shift by
  that much. Gaussian-vine densities in the upper tail change by up to 2e-8
  and now match their closed forms.
- Khoudraji h-functions succeed at points where a base density is not finite;
  they raised an error there before.

## 0.4.0

- **Khoudraji is no longer a default candidate.** `family_set` defaults no
  longer include `"khoudraji"`; list it explicitly to keep the old candidate
  set.
- **Selected families may change.** Gaussian pairs are fitted by maximum
  likelihood instead of Kendall's tau inversion, two-parameter families get a
  joint polish, Student t degrees of freedom are continuous on `[2, 200]`,
  and Frank accepts negative parameters. Refit before comparing scores with
  0.3.
- **Python errors.** `InvalidInputError` now also inherits from `ValueError`.
  Unsupported family, rotation, criterion and method strings, and dimension
  mismatches at evaluation, raise `InvalidInputError` (before: bare
  `ValueError` or `ModelFitError`). Negative or too-large seeds and `n < 1`
  raise `InvalidInputError`; a non-integer `n` raises `TypeError`.
- `VineCopula.sample_conditional` draws from the seeded Rust generator, so
  its output for a given seed differs from 0.3 and no longer depends on
  NumPy's global state.

## 0.3.0

Version 0.3 changed several public contracts to correct distributions that were
previously evaluated or labelled incorrectly. Refit models whose scores will be
compared with new fits; numerical outputs and selected families may change.

### Stored vines and pair orientation

A pair on an edge with `conditioned=(i, j)` represents `c(U_i, U_j)` in that
order. Version 0.2 runtime evaluation could reverse asymmetric pairs. Serialized
vines now include `format_version: 1`; loading an unversioned or unknown version
raises an error. Adding a version field to an old payload is not a migration.

Refit from the original observations, or explicitly rebuild a model with
`VineCopula.from_trees` after checking each pair's orientation against the model
you intend. Keep 0.2 available separately when you need to reproduce old outputs.
No automatic conversion can infer whether you intended the old fitted score or
the different distribution its runtime evaluated.

### HAC likelihood and fit options

`log_pdf` now works only for flat HACs with an implemented joint density.
For nested HACs, use `composite_log_pdf` explicitly. This returns pairwise
composite scores, which are not a normalized multivariate density.

The default fit method is `composite_mle`; `recursive_mle` remains an alias.
`tau_init` performs initialization only. `full_mle`, `smle`, and `dmle` raise
unsupported-method errors. Set `mc_samples=0` (the new default): nonzero values
are rejected because simulated likelihood is not implemented.

Fit diagnostics now include `likelihood_kind` (`joint` or `composite`). Ordinary
AIC and BIC are NaN for composite scores. Python's diagnostic constructors
default the new field to `joint`; Rust struct literals must provide it.

### TLL fitted state

Rust `TllParams` fields are private. Use `method()`, `bandwidth()`,
`effective_df()`, `grid_min()`, `grid_max()`, and `log_density()` accessors.
The density grid and derived marginal transforms must remain consistent.

Python `PairCopula.from_spec` accepts the optional `state` keyword. Preserve it
when copying `.spec`, vine edges, or factor links; scalar parameters alone
cannot reconstruct TLL. For example, `PairCopula.from_spec(**model.spec)` keeps
the fitted grid. Refit old TLL models to use the corrected smoothing rule and
normalized density rather than interpreting their numerical scores as unchanged.

### Factor integration cost and accuracy

All-Gaussian links use an exact Gaussian identity. Other links now refine the
latent integral by interval. `quadrature_max_nodes` caps integrand evaluations
per row throughout fitting and inference; `quadrature_rel_tol` sets the
estimated relative error target. The defaults are 4096 and `1e-7`.

Set `adaptive_quadrature=False` to use exactly `quadrature_nodes` without a
convergence guarantee. Fixed mode can be useful for bounded-cost exploration;
compare its result with adaptive evaluation before relying on likelihoods.
See [factor copulas](/guides/factor-copulas) for both APIs.

Standard errors may be NaN when Hessian checks fail. `converged=False` is
expected when joint polishing is disabled. Integration failures raise an
explicit numerical error; NaN and positive infinity are not converted to zero
density. A valid zero-density row is represented by `-inf`.
